# Бэкстейдж

Стриминговая платформа «Twitch-типа» с публичными и приватными эфирами: авторизация через Telegram, проверка платной подписки на приватный ТГ-канал, транскодинг в несколько качеств и Twitch-подобный чат.

- **Стриминг-движок — Owncast**: готовая open-source платформа берёт на себя RTMP-инжест, транскодинг и HLS. Мы не изобретаем велосипед — мы делаем поверх него премиальную витрину.
- **Публичные и приватные эфиры**: при старте эфира пульт спрашивает «приватный ли эфир?» и, если да, — какой Telegram-канал должен быть в подписках зрителя (выбор из реестра ТГК). Публичный эфир открыт всем, приватный гейтится **на уровне HLS-прокси** (403), а не только UI.
- **Транскодинг + выбор качества**: лестница вариантов Owncast — «Источник (1080p60) / 720p60 / 480p / 360p / Авто» прямо в меню плеера (fps подтягивается из конфига движка). Есть кнопка «Клип» (заглушка).
- **Twitch-подобный интерфейс**: тема «ГРАФИТ» — шершавый тёмный монохром без цветовых акцентов, бесцветные (прозрачные) панели, минимум оконтовки, жирные КАПС-заголовки, плеер вплотную к краям. Разделы «В Эфире / Главная / Клипы / Записи / Коллаборации / Расписание».
- **Чат как в Twitch**: сообщения `бейджи Имя: текст` без аватарок, hover-подсветка строк, поле ввода с кнопкой «ЧАТ», бейджи ролей (владелец / модератор / VIP / платный подписчик), кнопка «Кто в чате» (community drawer), эмодзи 7TV/BTTV/FFZ, модерация, команды, REST API для ботов и оверлей для OBS. Панель чата **сужается/расширяется drag-ом** (ширина запоминается), сворачивается кнопкой; на узких экранах держится справа, внизу — только мобильные.
- **Инфо-бар эфира 1:1 Twitch**: круглый аватар с красным кольцом и плашкой LIVE под ним, заголовок эфира → никнейм → категория и теги, справа компактные кнопки «Подписаться/Отслеживать» и счётчик зрителей.
- **«О канале» с редактором панелей**: под трансляцией — описание и сетка панелей (картинка + заголовок + текст + ссылка). У автора — редактор 1:1 как на Twitch: правка описания, добавление/удаление/перестановка панелей (PUT `/api/channels/[slug]/panels`).
- **Настройки канала** (для автора, шестерёнка в топбаре): внешний вид (никнейм, аватар, баннер, слоган) и трансляция (адрес RTMP-сервера, ключ с показом/копированием/сбросом, режим чата — заглушка).
- **Поиск по сайту**: строка в топбаре — ищет каналы, клипы и записи по словам (кириллица без учёта регистра), клик — переход к каналу/разделу.
- **Кнопки подписки**: платная подписка → «Подписаться» (оформление в Telegram-канале), бесплатная → «Отслеживать» (уведомления о старте эфира).
- **Сайдбар Twitch-стиля**: заголовок «ДЛЯ ВАС», развёрнутый список каналов / компактный рельс с аватарами — переключается одной кнопкой (запоминает выбор).
- **Mobile / Desktop**: адаптивный интерфейс (левый рейл → нижняя навигация, чат → сворачиваемый блок).
- **Легковесно, без Docker**: Next.js (App Router) + SQLite + Owncast (одиночный бинарь) + маленький socket.io-сервис чата на Bun.

## Архитектура

```
┌──────────────────────────────────────────────────────────────────┐
│                      OBS / энкодер стримера                      │
└─────────────────────────────┬────────────────────────────────────┘
                              │ RTMP rtmp://<server>:1935/live/<ключ>
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  Owncast v0.3.0 (mini-services/owncast, HTTP :8080, RTMP :1935)  │
│  ─ приём RTMP, транскодинг в варианты качества (ffmpeg)          │
│  ─ HLS: /hls/stream.m3u8 → 0/stream.m3u8 → сегменты .ts          │
│  ─ публичный статус: /api/status, /api/config                    │
└─────────────────────────────┬────────────────────────────────────┘
                              │ серверный fetch
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  Next.js 16 «Бэкстейдж» (порт 3000)                              │
│  ─ витрина GLASS ARENA + hls.js-плеер                            │
│  ─ /api/stream/hls/* — прозрачный HLS-прокси (гейт подписки!)    │
│  ─ /api/channels — мерж реального статуса Owncast в каналы       │
│  ─ /api/admin/demo-stream — демо-эфир: ffmpeg → RTMP (без OBS)   │
│  ─ Telegram Login + проверка подписки (Bot API)                  │
│  ─ Prisma + SQLite                                               │
└─────────────────────────────┬────────────────────────────────────┘
                              │ HTTP (внутренние вызовы)
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  chat-service (порт 3003, Bun + socket.io)                       │
│  ─ комнаты каналов, HMAC-токены, rate-limit, presence            │
│  ─ модерация (/ban /unban /mod /unmod /slow …), демо-чат         │
│  ─ эмодзи 7TV/BTTV/FFZ, оверлей для OBS, REST API                │
└──────────────────────────────────────────────────────────────────┘
```

**Почему так:** браузер тянет HLS через прокси `/api/stream/hls/*` внутри Next.js — это решает сразу три задачи: единый внешний порт (без CORS и лишних портов), приватность (плейлист и сегменты отдаются **только подписчикам** — гейт на уровне API, а не UI) и пер-канальную привязку инстансов Owncast в будущем.

| Компонент | Путь | Назначение |
|---|---|---|
| Основное приложение | `src/` | витрина + API + авторизация + HLS-прокси |
| Стриминг-движок | `mini-services/owncast/` | Owncast: RTMP-инжест → HLS |
| Чат-микросервис | `mini-services/chat-service/` | socket.io: комнаты, антифлуд, presence |
| Адаптер Owncast | `src/lib/owncast.ts` | статус/мерж, кэш 5с, деградация в ручной режим |
| Схема БД | `prisma/schema.prisma` | Users, Channels (owncastBaseUrl), Chat, Schedule, Clips… |
| Сиды витрины | `scripts/seed.ts` | канал dypaGPT, расписание, клипы |

## Быстрый старт

```bash
# 1. Зависимости
bun install

# 2. База + демо-данные
cp .env.example .env    # при необходимости поправьте DATABASE_URL
bun run db:push
bun scripts/seed.ts

# 3. Стриминг-движок Owncast (порт 8080 HTTP, 1935 RTMP)
bun scripts/fetch-owncast.ts   # скачает бинарь Owncast v0.3.0 (один раз)
cd mini-services/owncast
bun run dev                    # upstream: owncast.online

# 4. Чат-сервис (порт 3003)
cd mini-services/chat-service
bun install
bun run dev

# 5. Приложение (порт 3000)
bun run dev
```

Откройте `http://localhost:3000`. Вход — через **демо-режим** (роль и статус «платного подписчика» выбираются в диалоге входа), эфир — через кнопку **«ДЕМО-ЭФИР (FFMPEG)»** в пульте владельца: ffmpeg пушит тестовый RTMP-поток в Owncast, и через пару секунд плеер показывает живое видео. Это проверка всего конвейера без OBS.

## Как вещать (OBS)

1. Откройте **Пульт эфира** (шестерёнка в шапке, только ADMIN).
2. **Перед запуском эфира** пульт спросит: «приватный ли эфир?» — и если да, предложит выбрать **Telegram-канал из реестра**, который должен быть в подписках зрителя (реестр ведётся через `/api/admin/telegram-channels`). Режим можно сменить и для идущего эфира кнопкой «ИЗМЕНИТЬ».
3. Скопируйте **RTMP-сервер** и **Стрим-ключ Owncast**.
4. OBS → Настройки → Вещание: сервер = RTMP-адрес, ключ = стрим-ключ.
5. Начните вещание — Owncast включит эфир, витрина автоматически покажет «В ЭФИРЕ» (статус опрашивается каждые 5–10с), плеер откроет HLS через гейт подписки.

Эфир, зрители и время старта приходят из движка — ручного переключателя больше нет. Если Owncast недоступен, канал деградирует в ручной режим (isLive из БД) — витрина не ломается.

## Настройка Telegram (продакшен)

1. **Бот**: создайте бота у [@BotFather](https://t.me/BotFather), скопируйте токен → `TELEGRAM_BOT_TOKEN`.
2. **Login Widget**: у BotFather выполните `/setdomain` и укажите домен сайта. Username бота → `TELEGRAM_BOT_USERNAME`.
3. **Приватный канал**: создайте приватный канал, добавьте бота его **администратором** (иначе Bot API не увидит участников). Числовой ID канала (начинается с `-100…`) → `TELEGRAM_CHAT_ID`; можно взять через пересылку сообщения боту [@userinfobot](https://t.me/userinfobot).
4. **Приглашение**: ссылка-инвайт в канал → `TELEGRAM_CHANNEL_LINK` (кнопка «Оформить подписку» в гейте).
5. **Админы**: ваши Telegram ID/username через запятую → `ADMIN_IDS`.
6. **Секреты**: задайте собственные `CHAT_SECRET` и `INTERNAL_SECRET` в `.env` **и** в окружении chat-сервиса (должны совпадать).

## Переменные Owncast

```ini
OWNCAST_URL=http://127.0.0.1:8080   # база инстанса (в проде — https://owncast.example.com)
OWNCAST_RTMP_URL=rtmp://host:1935/live  # то, что видит стример в OBS
OWNCAST_STREAM_KEY=bs-dypaGPT       # флаг -streamkey в mini-services/owncast/run.ts
OWNCAST_ADMIN_PASSWORD=…            # доступ к /admin самого Owncast
```

Канал можно привязать к **отдельному** инстансу Owncast: поле `owncastBaseUrl` у Channel (PATCH в API) — фундамент мультиканальности: один канал = один движок.
